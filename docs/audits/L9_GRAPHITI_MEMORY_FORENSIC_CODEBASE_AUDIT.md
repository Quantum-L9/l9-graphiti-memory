# L9 Graphiti Memory — Forensic Codebase Audit

## Executive verdict

The canonical architecture (MemoryService as sole control plane, atomic
record+receipt+status+outbox commit, projections as rebuildable derivations,
bi-temporal records, capability-gated store mutations) is real in code and
mostly sound. The audit found no P0 integrity or security defect that exposes
content across tenants or bypasses authentication. It found eight P1 runtime
correctness defects, all at seams the ADR ledger already governs, where the
implementation diverges from its own law:

- lifecycle transitions performed by scheduled maintenance never retire the
  projection (ADR-074 violated on the maintenance path);
- a delayed or retried `memory.record.project` event re-materialises a
  superseded, archived, or deleted record in the provider and leaves a live link;
- a verified deletion whose record has no live projection link retries to
  DEAD and stays `deletion_pending` forever;
- governed writes fail permanently in any namespace holding more than 1,000
  active records because the service digests a truncated snapshot and the
  store digests the full one;
- bearer-token principals silently lose their configured `maintain_namespaces`;
- a record in any state, including a deletion tombstone or a quarantined
  candidate, can be superseded into `SUPERSEDED`;
- `RecordStore.transition_state` is a canonical mutation that requires no
  service capability, so in-process code can flip a quarantined record to active;
- the temporal contract accepts naive datetimes although ADR-029 requires
  timezone-aware UTC, which corrupts SQLite's lexical time comparisons and
  turns in-memory comparisons into silently FAILED search receipts.

Every P1 and the selected P2 hardening items are repaired at their canonical
owner with regression proof; see the repair handoff for evidence.

## Write path

`CLI/MCP/SDK/importers → MemoryPrincipal → MemoryService.write → NamespacePolicy.evaluate → normalize_candidate → operation identity (explicit key or minted uuid) → find_by_idempotency (explicit key only) → AdmissionEngine.evaluate → MemoryRecord + TemporalCoordinates(recorded_at=service clock) → status events (initial + supersessions) → outbox events (project self; retire superseded) → RecordStore.commit_write (one transaction; optional phase-lock precondition re-verified inside) → WriteReceipt`.

## Read path

`search → authorized namespaces → recorded_before defaults to now → RetrievalPlanner → store.search_records (tenant, namespaces, state, confidence, valid_at, recorded_before, class; most-recent `limit*20`) → projection strategies (graph/semantic) scored by record_id → ranking → SearchReceipt with strategy/store attempt evidence`. Hydration wraps search with `ContextBudgetAllocator`.

## Persistence model

Three adapters implement one contract. SQLite serialises writes with a process
RLock plus `BEGIN IMMEDIATE`; PostgreSQL uses per-thread connections,
`FOR UPDATE`, `SKIP LOCKED` for outbox claims, and a transaction-scoped
advisory lock for governed writes. `record_json` is the source of truth per row
and is upcast through `schema_registry` on read.

## Identity and idempotency

Record identity is a service-minted UUID. Operation identity is the caller's
`idempotency_key` or `operation:{namespace}:{uuid4}` (ADR-071). Unique index on
`(tenant_id, namespace, idempotency_key)`. Projection identity uses the record
UUID as the Graphiti episode `uuid`, so re-projection is idempotent at the
provider.

## Evidence and provenance

`Provenance`, `EvidenceRef`, `Confidence` survive into the canonical record
unchanged; the projection payload is deliberately lossy (content, assertion,
temporal, confidence score, tags, source digest) but carries the record id, and
retrieval always hydrates from canonical records — projection hits that do not
resolve to a canonical record are dropped, never surfaced.

## Temporal model

`valid_from/valid_to` (half-open), `recorded_at` (service clock),
`superseded_at` (set on SUPERSEDED transition). Search filters valid time and
transaction time independently. Supersession and archive append status events
and never rewrite content.

## Authorization and namespace

Server-derived `MemoryPrincipal`; glob grants per action; `is_admin` is
tenant-scoped; `is_global_admin` is the only cross-tenant claim. Maintenance
holds its own `MAINTAIN` grant.

## Graphiti projection

`OutboxWorker` → `GraphitiProjection.project` → `HttpMcpTransport.write`
(`add_memory` with `uuid=record_id`, `group_id=namespace`) → `ProjectionLink`
locator persisted. Retire and erase both call `delete_episode` with the
persisted locator (ADR-076 ceiling), distinguished in canonical state by the
retirement receipt versus the deletion receipt.

## Replay and rebuild

Rebuild lists active records without a live link for the configured provider
and enqueues `memory.record.project` events with `rebuild: true`. Lineage
replay walks supersedes/references/conflicts_with/provenance edges over the
authorized namespace.

## Failure and retry

Outbox: leased claims, bounded attempts with exponential backoff, DEAD terminal
state, lease-loss reporting. Store failures propagate as `StoreError`; no
deferred ingestion path exists (ADR-070, structurally scanned).

## Package and runtime

`pyproject.toml` declares only `pydantic` and `pyyaml` as hard dependencies;
package data includes resources and the projection schema; three console
scripts. The release script builds the wheel and installs it into an isolated
target, then exercises resolve/health/tool inventory/Cursor client lifecycle.

## Findings register

Severity: P0 integrity/security, P1 runtime correctness, P2 material
hardening, P3 non-blocking debt, INFO.

### P0 findings

None.

### P1 findings

**F-01 AUTHORIZATION** — `authz/authenticator.py:_principal_from_config` omits
`maintain_namespaces`. Call path: HTTP `/mcp` → `TokenAuthenticator.authenticate`
→ `MemoryPrincipal` → `NamespacePolicy.evaluate(MAINTAIN)`. Expected: a token
configured with `maintain_namespaces=("repo-a",)` can run maintenance and
rebuild. Actual: the principal has `maintain_namespaces=()`, every MAINTAIN
request is denied; nightly maintenance over HTTP is impossible without admin.
Reproduced. Root cause: field dropped when MAINTAIN was added (ADR-075). Fix at
owner: pass the field. Regression: unit test asserting parity between
`TokenPrincipalConfig` and the authenticated principal.

**F-02 GRAPHITI_PROJECTION / REPLAY** — `services/outbox_worker.py`
`memory.record.project` handler projects whatever the record's current state is.
Call path: write A → supersede/archive/delete A → project(A) delivered late or
retried after retire(A)/erase(A). Expected: a record that is no longer active is
never (re)projected. Actual: the superseded/archived/deleted content is written to
the provider and a fresh `ProjectionLink` is saved; for a tombstone the deletion
is already COMPLETE, so the tombstone lives in Graphiti with no erase pending.
Reproduced. Root cause: no lifecycle check before `projection.project`. Fix:
treat a non-active aggregate as satisfied (delivered, nothing projected) and log.

**F-03 FAILURE_SEMANTICS / DELETION** — `services/outbox_worker.py`
`memory.record.erase` raises when no `ProjectionLink` exists. Call path:
retire(A) deletes the link → later `delete(A)` → erase(A) → RuntimeError → RETRY
… DEAD. Expected (ADR-074 already says so for retire): nothing to erase means
erasure is satisfied and the deletion completes. Actual: `DeletionReceipt`
stays `pending_projection`, record stays `deletion_pending` forever. Reproduced.
Fix: complete the deletion when no link exists; F-02 guarantees no later
project event can re-materialise the tombstone.

**F-04 GRAPHITI_PROJECTION / ARCHITECTURE** — `maintenance/service.py`
`_apply_supersede` and `_apply_archive` call `store.transition_state` directly.
Expected (ADR-074 invariant): every supersession and archive emits
`memory.record.retire` in the same transaction as the transition. Actual: the
record becomes SUPERSEDED/ARCHIVED with no retire event; the provider keeps
serving the stale fact to any direct Graphiti consumer; no receipt records the
transition. Reproduced (retire_events=0, link live). Root cause: maintenance
bypasses the service for lifecycle changes. Fix: new `MemoryService.transition_lifecycle`
committing status events, a lifecycle receipt, and retire events atomically via
a new capability-gated `RecordStore.commit_lifecycle`.

**F-05 AUTHORIZATION / ARCHITECTURE** — `RecordStore.transition_state` requires
no `ServiceWriteCapability` (`in_memory_store.py`, `sqlite_store.py`,
`postgres_store.py`). Any in-process holder of the store can move QUARANTINED →
ACTIVE (skipping review) or DELETED → ACTIVE. AGENTS.md invariant 6 and ADR-036
say canonical mutations require the capability. Fix: gate `transition_state`
with the capability, make it a guarded method in the bypass scanner, and remove
maintenance from the direct-transition allowlist (it now goes through the
service).

**F-06 IDENTITY / PHASE-LOCK** — `MemoryService.conflicts` lists active records
with the store default `limit=1_000`; `PhaseLockPrecondition` digests are
verified by the stores over all active rows (`_require_phase_lock_snapshot`).
Expected: identical digests when nothing changed. Actual: with >1,000 active
records `write_governed` always raises `PhaseLockSnapshotConflict`, and conflict
detection/phase-lock grants ignore older records. Reproduced with 1,001 records
on SQLite. Fix: unbounded snapshot listing (`limit=None`) in the store contract
and its use in `conflicts`.

**F-07 TEMPORAL / STATE MACHINE** — `MemoryService._admit` accepts `supersedes`
targeting a record in any state. Expected: only a current record (ACTIVE,
SUPERSEDED, ARCHIVED) can be superseded. Actual: DELETION_PENDING/DELETED
tombstones become SUPERSEDED (contradicting the COMPLETE deletion receipt) and
QUARANTINED candidates exit review without approval. Reproduced. Fix: reject
with `AdmissionError` at the owner.

**F-08 TEMPORAL / CONTRACT** — `contracts/temporal.py`, `contracts/requests.py`
accept naive datetimes. ADR-029: all values timezone-aware UTC. SQLite stores
`isoformat()` text and compares lexically, so a `+02:00` `valid_from` sorts and
filters incorrectly against UTC values; in-memory comparison raises TypeError,
which `RetrievalPlanner` swallows into a FAILED receipt. Fix: shared validator
that rejects naive values and normalises aware values to UTC on every temporal
field of records and requests.

### P2 findings

**F-09 IDEMPOTENCY** — same `idempotency_key`, different payload returns
DUPLICATE with no signal (`_admit`). Fix: warning naming the digest mismatch.

**F-10 IDEMPOTENCY / CONCURRENCY** — duplicate lookup runs outside the commit;
two concurrent same-key writes → UNIQUE violation → generic `StoreError` instead
of DUPLICATE. Fix: typed `IdempotencyConflict` from all stores, resolved by the
service into a DUPLICATE receipt.

**F-11 EVIDENCE** — `commit_deletion`/`complete_deletion` append no
`MemoryStatusEvent`; the append-only lifecycle ledger has no record of
→DELETION_PENDING/→DELETED. Fix: status events inside both transactions.

**F-12 RETRIEVAL / PROJECTION** — projection hits whose records fall outside
the store's most-recent `limit*20` window are dropped, so graph/semantic
strategies cannot surface older relevant records. Fix: hydrate missing hit
record ids from the canonical store under the same filters.

**F-13 DELETION** — deleting a DELETED/DELETION_PENDING record issues a second
tombstone, receipt, and erase event. Fix: refuse with `AdmissionError`.

**F-14 ACTIVE / LEASE** — `active/inmemory.py:renew` checks the lease stored
at registration and never refreshes it; the SDK heartbeats with the same lease
object, so every session re-registers after one lease TTL. Redis `renew` checks
no lease at all (conformance divergence). Fix: track lease expiry from the last
successful heartbeat in both adapters; authenticate `lease_id`.

**F-15 ACTIVE / ISOLATION** — Redis `list_active` ignores
`scope.deployment_id`; in-memory `unregister` leaks the context version counter
(next registration starts at N+1, Redis at 1); `list_active(limit<=0)` raises
IndexError in memory. Fix at the adapters.

**F-16 EVIDENCE / SECRETS** — `client_config/mcp_probe.py` redacts stderr only
for env values whose name looks secret; a `scheme://user:pass@host` URL in a
traceback is persisted in the probe receipt. Fix: also redact userinfo in URLs.

**F-17 PERSISTENCE / PORTABILITY** (found during repair validation, not in the
initial lock) — `adapters/postgres_store.py:_insert_status_event` parses a
record payload's `superseded_at` with `datetime.fromisoformat`. The payload
carries two spellings of UTC: `+00:00` from `isoformat()` when the store
applies a supersession, and `Z` from pydantic's JSON mode whenever the record
is re-serialised (tombstone redaction in `commit_deletion`, any `commit_write`).
Python 3.10, which CI runs, rejects `Z`; 3.11+ accepts it. Before this repair
no path parsed the value after a re-serialisation; the F-11 repair (deletion
status events) made `complete_deletion` do so, and the 3.10 PostgreSQL leg
failed deterministically on a superseded record's deletion. Fix at the owner:
a Z-tolerant `_parse_timestamp` helper, consistent with the existing pattern
in `cli.py` and `mcp_tools.py`. Proven by the full suite under Python 3.10.20
and 3.13 against PostgreSQL 16.

### P3 / INFO

- `MaintenanceService` uses `MemoryService._admit` (private) — accepted,
  documented; not changed.
- `GeneratedDataService.invalidate_by_source` records an event only
  (`matched=0`) and falls back to namespace `"default"` — documented debt.
- `GeneratedDataService.search_context` derives `token_budget` below the
  contract minimum for `max_characters < 256` — fixed (clamped).
- CLI `prune --dry-run` is parsed and ignored — fixed (dry-run wins).
- Quarantine has no explicit approval transition; the only exits are admin
  promotion (class change required) or deletion — UNKNOWN intent, left as is.
- `MemoryRecord.conflicts_with` is never populated by any producer — INFO.
- Graphiti "episode not found" on retire/erase dead-letters rather than being
  treated as already withdrawn — documented debt (provider error strings are
  not parsed).
- `AdmissionError` was defined but unused — now used for F-07/F-13.
